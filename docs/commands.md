# コマンド（繰り返しタスク）

タスク行に `==>` を書いておくと、そのタスクを完了したときに次のタスクが生まれます。生まれる日付、いつまで続けるか、内容をどう変えるか、どこへ片付けるかを、`==>` に続く節で指示します。

```markdown
- [ ] ゴミ出し @2026-08-18 ==> every tue,fri
```

この行のチェックを付けると、次の金曜日のゴミ出しが生まれ、完了した行からは `==>` が消えます。


## 発火の規則

完了扱いのステータスを付けた瞬間に発火します。どの文字を完了扱いにするかは設定（Status Definitions）で決めるので、`[x]` 以外を完了扱いにしていれば、それでも発火します。

**発火したコマンドは消えます。** 生成が終わると、完了した行から `==>` 以降が取り除かれます。同じ行のチェックを外して付け直しても、二重には生まれません。

`until` を過ぎていた、`xN` を使い切っていた、という理由で次のタスクが生まれなかったときも、コマンドは消えます。もう働かないコマンドが行に残り続けることはありません。

式の評価に失敗して発火できなかったときは、理由が通知として表示され、ファイルには何も書きません。


## いつ生成するか

日付の決め方は 3 通りあり、遅れて完了したときの振る舞いで選び分けます。スケジュールの節は 1 つのコマンドに 1 つだけ書けます。

| 節 | 書き方 | 遅れて完了したとき |
|---|---|---|
| `every` | `every tue,fri`、`every 2w`、`every mo@25` | 次の周期点まで飛ばします |
| `+n` | `+3d` | 基準日 + n をそのまま使うので、過去の日付が積みます |
| `at(式)` | `at(today + 3d)` | 式が答えたとおりになります |

```markdown
- [ ] ゴミ出し @2026-08-18 ==> every tue,fri
- [ ] 英単語 @2026-08-18 ==> +3d
- [ ] 水やり @2026-08-18 ==> at(today + 2d)
```

上から順に、暦のルーチン、飛ばしたくない連続、やった日から数えるもの、という使い分けになります。

### every の書き方

| 書き方 | 意味 |
|---|---|
| `every mon` | 毎週月曜 |
| `every tue,fri` | 毎週火曜と金曜 |
| `every 2w` | 2 週間ごと（単位は `min` `h` `d` `w` `mo` `y`） |
| `every mo@25` | 毎月 25 日 |
| `every mo@last` | 毎月末 |
| `every 2mo@15` | 2 か月ごとの 15 日 |

`every` の次の日付は、完了した日と元の日付のうち遅いほうより後にある、最初の周期点です。3 日遅れてゴミ出しを完了しても、次は今週の残りか来週であって、遅れた分が積むことはありません。

存在しない日を指した月は月末に丸めます（`every mo@31` の 2 月は 28 日か 29 日）。月末を意図しているなら `every mo@last` と書くほうが読み手に伝わります。

### 基準日

`start`、`end`、`due` の順で最初に見つかった日付が基準日です。日付ブロック全体が基準日の移動分だけ平行移動するので、`@2026-08-18T09:00>10:30` のように幅を持つタスクは、幅を保ったまま次の日付へ移ります。

日付を 1 つも持たないタスクは、完了した日を基準日とみなします。


## いつまで生成するか

| 節 | 書き方 | 意味 |
|---|---|---|
| `xN` | `x14` | あと N 回。生成のたびに 1 つ減り、`x1` で生まれたタスクにはコマンドが付きません |
| `until(式)` | `until(2026-09-28)` | 次の日付がその日以前なら生成します（その日ちょうどは含みます） |

両方書けます。先に尽きたほうで止まります。

```markdown
- [ ] 家賃 @2026-08-25 ==> every mo@25 until(2027-03-25)
- [ ] 準備体操 @2026-08-18 ==> +1d x14
```

`xN` の残り回数はタスク行に書かれている数字そのものです。プラグインの外に状態を持たないので、行を読めば残りが分かりますし、数字を書き換えれば残り回数が変わります。


## 生成物を整える

日付をずらすだけでは足りないとき、setter で内容や日付を上書きします。それぞれ 1 つのコマンドに 1 つだけ書けます。

| 節 | 変えるもの |
|---|---|
| `setContent(式)` | 内容 |
| `setStart(式)` `setEnd(式)` `setDue(式)` | 日付 |
| `setStartTime(式)` `setEndTime(式)` `setDueTime(式)` | 時刻だけ |

```markdown
- [ ] 週報 @2026-08-17 ==> every mon setContent("週報 " + format(start, "MM/DD"))
- [ ] 提出 @2026-08-17 ==> every mon setDue(start + 3d)
```

setter が見るのは、**日付をずらしたあと**の値です。上の例の `start` は、生まれてくるほうの月曜日を指します。

日付を渡すと時刻は消えます。日時を渡すとその時刻になります。時刻だけを変えたいときは `setStartTime` などを使います。

`until` の判定はスケジュールが決めた日付で行うので、setter のずらしは `until` からは見えません。


## どこへ片付けるか

`move(...)` を書くと、完了したタスクが指定のノートへ移ります。移るのは完了したほうで、新しいタスクは元の場所に生まれます。

```markdown
- [ ] 週報 @2026-08-17 ==> every mon move([[Log/Done]])
```

宛先は式でも書けるので、月ごとのノートへ振り分けることもできます。

```markdown
- [ ] 週報 @2026-08-17 ==> every mon move([[Log/]] + format(done, "YYYY-MM"))
```


## 子タスクを作る

**子行はコピーされません。** 生まれるのはタスク行 1 行です。子タスクを持つタスクを繰り返したいときは、`use("名前")` で生成ブロックを指定します。

```markdown
- [ ] 週報 @2026-08-17>2026-08-21 ==> every mon use("週報")
```

````markdown
```tv-gen 週報
- [ ] 週報 ${dates}
    - [ ] 数字を集める
    - [ ] 下書き
```
````

ブロックの書き方は [生成ブロック](gen.md) にあります。


## 世代をまたぐ値

`state(名前: 初期値)` で宣言した値（セル）は生成ブロックの中で `state.名前` として読み書きでき、書き換えた値が次のタスクへ渡ります。連番や、回ごとに変わる間隔を作るのに使います。

```markdown
- [ ] 読書会 @2026-08-17 ==> every mon state(n: 1) use("読書会")
```

````markdown
```tv-gen 読書会
- [ ] 第${state.n = state.n + 1}回 読書会 ${dates}
```
````

初期値はリテラルだけです。発火のたびに現在値が行に書き戻されるので、行を読めば次が何回目かが分かります。


## 複数行で書く

節が増えて 1 行が長くなったら、タスク行の直下に `- ==>` で始まる行を足して分けられます。意味は 1 行に書いた場合と同じです。

```markdown
- [ ] 週報 @2026-08-17 ==> every mon
    - ==> setContent("週報 " + format(start, "MM/DD"))
    - ==> setDue(start + 3d)
```

1 つの節を途中で改行することはできません。節はどれか 1 行に収めます。


## 書き間違いの見え方

コマンドの誤りは、書いている最中にエディタが波線で知らせます。波線にカーソルを合わせると、何が問題で何を書けばよいかが表示されます。

| 書いたもの | 出るもの |
|---|---|
| `every` の後ろに周期がない | 周期の書き方（曜日、`2w` のような間隔、`mo@N`）を示します |
| スケジュールの節が 2 つ | 1 つだけ書けることを示します |
| `nochildren` | 退役した節であることを示します。子行はもうコピーされないので、消して構いません |
| 節の中で `state.名前` を読んだ | セルを読めるのは生成ブロックの中だけであることを示します |

式そのものの誤り（型が合わない、この言語にない名前）も同じように波線で出ます。書ける式は [式リファレンス](expressions.md) にまとまっています。
