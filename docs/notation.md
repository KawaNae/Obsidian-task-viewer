## プロパティ

プロパティは、タスクに付ける `キー: 値` の組です。カードの色や線種のように Task Viewer が意味を持たせる組み込みのキーと、利用者が自由に付けるカスタムプロパティがあります。どちらも同じ記法で書き、同じ規則で受け継ぎます。

### 書く場所

プロパティは3つの層に書けます。

- ノート: frontmatter に書きます。ノートの中のすべてのタスクが受け継ぎます
- セクション: 見出しの下に `- key:: value` の項目を字下げなしで書きます。そのセクションと、下の階層の見出しのセクションのタスクが受け継ぎます
- タスク: タスクの直下の子の項目に `- key:: value` を書きます。そのタスクだけの値です

```markdown
---
area: home
---
## 2026-10-12
- tv-color:: teal

- [ ] 買い物
    - area:: errand
- [ ] 掃除
```

この例では、「買い物」の `area` は `errand`、「掃除」の `area` はノートから受け継いだ `home` です。どちらのタスクも、セクションの `tv-color` の `teal` を受け継ぎます。

書く位置には次の決まりがあります。

- セクションのプロパティ行は、セクションの中の字下げなしの項目なら、どこに書いてもセクションのものです。最初のタスクより下に書いてもかまいません。ただし、見出しの直下にまとめて書くことを推奨します
- タスクのプロパティ行は、タスクの直下の子だけです。それより深い位置の `- key:: value`（子の項目のさらに下など）は、どの層のプロパティにもなりません
- 最初の見出しより上にある `- key:: value` は、見出しのないセクションのプロパティです。値が届くのは、最初の見出しより上にあるタスクだけです。ノート全体に効かせる値は frontmatter に書いてください
- 箇条書きの記号は `-` のほかに `*`、`+`、番号（`1.`）も使えます。コードブロックの中の行はプロパティになりません
- タスクの字下げを忘れると、そのタスクのつもりのプロパティ行がセクションのプロパティになり、セクションのすべてのタスクに値が届きます。カードやハブに受け継いだ値として出るので、そこで気づけます

タスクはタスクから値を受け継ぎません。親のタスクの下に書いたプロパティは、子のタスクには届きません。

### キー

行のプロパティのキーは、箇条書きの記号と空白の後から最初の `::` までの文字列で、前後の空白を除いたものです。

- `:`、`[`、`]`、`` ` `` を含むキーは使えません。そのキーを書いた行はプロパティ行でなく、ふつうの項目として読みます
    - `[` と `]` を除くのは、チェックボックスの行とリンクの行をプロパティ行として読まないためです
    - `` ` `` を除くのは、`` - 見出しの下に `- tv-color:: red` を書く `` のように、インラインコードでプロパティ行を引用した説明文を読まないためです
- 空のキー（`- :: x`）と空白だけのキーの行も、ふつうの項目です
- `**k**` や `#tag` は、記号を含めてそのままキーになります
- `- k::: v` は、キー `k`、値 `: v` と読みます

キーは、どの層でも大文字と小文字を区別しません。Obsidian のプロパティ（Properties ビュー、検索、型の記録）に合わせています。

- frontmatter の `area`、セクションの `AREA::`、タスクの `Area::` は同じプロパティで、近い層の値が使われます
- カード、ハブ、API に出るキーの綴りは、効いている値を書いた層の綴りです
- 組み込みのキーも同じです。`TV-COLOR::` も色、`Tags::` もタグとして読みます
- 文字の幅は揃えません。全角の `ａｒｅａ` は `area` と別のキーで、全角の `ｔａｇｓ::` はタグになりません

### 値の型

値の型は、書いた綴りから決まります。規則は、Obsidian が frontmatter を読む YAML 1.2 で、引用符なしで書いた値と同じです。

| 型 | 綴り |
|---|---|
| 数 | `5`、`-5`、`+5`、`.5`、`5.`、`1e3`、`0x1F`、`0o17`、`.inf`、`-.inf`、`.nan`。`017` は 10 進の 17 |
| 真偽値 | `true`、`True`、`TRUE`、`false`、`False`、`FALSE` |
| 値なし | 何も書かない、`null`、`Null`、`NULL`、`~` |
| テキスト | 上のどれでもないもの |

- テキストに引用符は要りません。`[[ノート]]`、`#tag`、`a: b`、`[a, b]`、`a, b` もテキストです
- `1,000`、`1_000`、`10:30`、`yes`、`on`、全角の `１２３` もテキストです
- 数や真偽値と同じ綴りのテキスト（数字だけの ID など）を書くときは、値全体を `"` か `'` で囲みます。`- id:: "123"` の値はテキストの `123` です
    - 値全体を囲むときだけ引用符として読みます。`"Hello" he said` は引用符を含めてテキストです
    - 全角の引用符（`“ ”`）は引用符として読みません
    - エスケープは読まず、引用符の内側をそのまま読みます
- カード、メニュー、候補には、引用符を外したテキストと、書いた綴りのままの数を出します（`0x1F` は `0x1F`）。ハブの欄には、行に書いた綴りをそのまま出します（`"123"`）
- API は値を型どおりに返します（[Public API](api.md#normalizedtask-フィールド)）。数は数（`0x1F` は 31）、値なしは `null`、引用符で囲んだテキストは引用符を外した文字列です

frontmatter の値の型は、YAML が決めます。引用符で囲んだ `"true"` はテキストです。値が連想配列のキー（入れ子のプロパティ）は、Obsidian と同じくプロパティとして読まず、タスクにも受け継ぎません。

### リスト

行でリストを書くときは、値のないプロパティ行の下に項目を1段深くして書きます。

```markdown
- [ ] 打ち合わせ
    - 参加者::
        - 田中
        - 佐藤
```

- 各項目の型は、1行の値と同じ規則で決まります
- `[a, b]` の形はリストになりません。テキスト `[a, b]` です
- 値のある行（`- 参加者:: 田中`）の下の項目は、リストに入らずメモとして残ります。エディタに警告が出ます
- 次の行はリストの項目になりません。エディタに警告が出ます
    - 値のない項目（`-`、`- null`、`- ~`）
    - チェックボックスの項目（`- [ ] x`）。タスクとして読みます
    - 項目の下に入れ子にした行。上の項目は読みます
    - 項目でない行（項目の本文の続き、引用、コードブロック）
- プロパティ行の形をした項目（`- name:: Kawa`）は、テキスト `name:: Kawa` の項目として読み、警告を出します。入れ子のプロパティは使えません。プロパティにするなら、1段浅くしてください
- 下に項目のない `- 参加者::` は、空のリストでなく値なしです。frontmatter の `key: []` に当たる空のリストは、行では書けません

frontmatter のリストは、YAML のリストで書きます。項目のうち、値なし、入れ子のリスト、連想配列は読みません。

### 継承と値なし

タスクの値は、frontmatter、セクション（上の階層の見出しから順に）、タスク自身の順に重ねて決まります。近い層に値があれば、その値が使われます。

- 値なし（`- key::` で下に項目のないもの、`- key:: null`、frontmatter の `key:`）は、「この層では値がない」という意味です。上の層の値を隠します
- 組み込みのキーにもカスタムプロパティにも、同じ規則が当たります
- リストは1つの値として扱います。近い層のリストが、上の層のリストを丸ごと置き換えます。項目は足し合わせません
- タグは例外で、層ごとのタグを足し合わせます（下の「タグ」）

継承した値を1つのタスクやセクションだけで打ち消すには、値のない行を書きます。

```markdown
## 作業
- tv-color:: red

- [ ] 赤いタスク
- [ ] 色のないタスク
    - tv-color::
```

キーだけを書いた行も値を隠します。書きかけのつもりで `- area::` だけを書いても、受け継いだ値が消えます。カードとハブに出る値で確かめてください。

### タグ

タグは、タスク行の本文の `#tag` と、`tags` のプロパティから読みます。どの層のタグも足し合わせ、上の層のタグを打ち消す方法はありません。値のない `- tags::` は何も足しません。

- 行の `tags::` は、値の中の `#tag` だけを読みます。`- tags:: #a #b` はタグ `a` と `b` です。`#` のない `- tags:: a, b` はタグになりません
- `- tags::` の下の項目も、各項目から `#tag` を読みます。`- #a` はタグ `a` で、`- b` はタグになりません。Obsidian が本文の `#a` をタグとし、`b` をタグにしないのに合わせています
- frontmatter の `tags` は、Obsidian と同じく、リストか1つの文字列で書きます。先頭の `#` は省けます。`tags: a, b` と `tags: a b` はタグになりません
- `tags` 以外のプロパティの値にある `#tag` は、タスクのタグになりません
- どの文字までがタグになるかは、Obsidian の規則と同じです。数字だけの `#123` はタグになりません

### 組み込みのキー

次のキーは Task Viewer が意味を持たせ、カスタムプロパティになりません。`tags` 以外のキーの名前は、設定で変えられます。

| キー | 値 | 書ける層 |
|---|---|---|
| `tv-start` | 開始の日付、時刻、またはその両方（`2026-10-12`、`11:00`、`2026-10-12T11:00`） | セクション、frontmatter |
| `tv-end` | 終了の日付、時刻、またはその両方 | セクション、frontmatter |
| `tv-due` | 締切の日付（時刻を付けてもよい） | セクション、frontmatter |
| `tv-color` | カードの色。16 進（`ff0000`、`#f00`）、CSS の色の名前（`red`）、CSS の色の式（`rgb(255 0 0)`） | すべて |
| `tv-linestyle` | カードの線種。`solid`、`dashed`、`dotted`、`double`、`dashdotted` | すべて |
| `tv-mask` | ビューのマスク表示がオンのとき、タスクの本文の代わりにカードに出す文字 | すべて |
| `tags` | タグ（上の「タグ」） | すべて |
| `tv-ignore` | `true` のとき、ノート全体を読み込みの対象から外す | frontmatter |

- タスクの日付は、タスク行の日付ブロック（`@…`）だけで書きます。タスクの下の `- tv-start::` などは読まず、エディタに警告が出ます
- 日付のキーで時刻だけを書くと、日付は上の層から受け継ぎます。値のない `- tv-start::` は、日付と時刻の両方を隠します
- `position`、`tv-status`、`tv-content`、`tv-timer-target-id` も、カスタムプロパティになりません。`position` は Obsidian が使い、ほかの3つは旧版がノートのタスクに使っていたキーです

### 読めない値と警告

組み込みのキーに、そのキーとして読めない値を書くと、書いていないものとして扱います。値なしと違って上の層の値を隠さず、上の層の値がそのまま届きます。行に書いたときは、エディタに警告が出ます。

- 読めない値の例
    - リスト（`tags` を除く）と、空のテキスト
    - 色として読めない `tv-color`（綴りを誤った `rde`）
    - 知らない線種（`wavy`）
    - 日付も時刻も指さない日付のキーの値、実在しない日や時刻（`2026-02-30`、`25:00`）、日付のない `tv-due`
    - frontmatter の日付のキーに書いた数（`tv-end: 630`）

行のプロパティの問題は、エディタの診断として問題の行に波線で出ます。文は、Task Viewer がその行をどう読んだかと、直し方を書きます。

| 問題 | 種類 |
|---|---|
| 同じタスクかセクションに同じキーを2行以上書いた | エラー |
| タスクの下に日付のキーを書いた | 警告 |
| 値のある行の下に項目を書いた | 警告 |
| リストの項目にプロパティ行の形を書いた | 警告 |
| リストの項目として読めない行を書いた | 警告 |
| 組み込みのキーに読めない値を書いた | 警告 |

タスク自身のプロパティに問題があると、Task Hub はそのプロパティの欄を編集できなくし、問題を欄の下に出します。欄から問題の行をエディタで開けるので、エディタで直してください。ほかの欄は編集できます。タスクの下の日付のキーの警告は、どの欄も止めません。frontmatter の問題は Task Viewer からは出しません。Obsidian の Properties ビューがエラーを出します。

### 重複したキー

同じタスクかセクションに同じキーを2行以上書くと、そのキーをどの行でも読まず、エディタにエラーが出ます。大文字と小文字だけが違うキー（`Area::` と `area::`）も同じキーです。

- そのタスクかセクションのほかのキーは読みます
- 読まなかったキーは書いていないものとして扱い、上の層の値が届きます
- 別の層に同じキーがあるのは、重複でなく継承の上書きです

frontmatter では次のとおりです。

- 同じキーを2回書くと、YAML として読めないので、Obsidian と同じく frontmatter 全体を読みません
- `Area` と `area` のように大文字と小文字だけが違うキーは、YAML としては読めますが、どちらのキーも読みません。Obsidian は2つの値を残しますが、Task Viewer のプロパティは値を1つしか持てないためです
- `tags` と `Tags` は例外で、Obsidian と同じく先に書いたキーのタグを読みます

### Task Hub での書き込み

Task Hub は、タスク自身のプロパティ行を書きます。セクションと frontmatter の値は編集できず、受け継いだ値の出所のラベルから、値を書いた行をエディタで開けます。

- 欄に入力した綴りのまま書きます。型は行と同じ規則で決まり、`123` は数、`"123"` はテキストです
- 受け継いだ値と同じ値を入力して確定しても、タスク自身の行として書きます。後でセクションの値を変えても、そのタスクは今の値を保ちます
- 値を空にして確定するか × を押すと、タスク自身の行を消し、上の層の値が届きます
- 受け継いだ値を使わないときは、出所のラベルの横の、丸に斜線のアイコンのボタンを押します。値のない行（`- key::`）を書き、上の層の値を隠します
- リストは項目ごとに追加、削除、編集、並べ替えができます。最後の項目を消すと、行も消えます。受け継いだリストは「このタスクの値にする」で項目を写してから編集します
- 新しいプロパティはテキストとしてだけ足せます。リストのプロパティを新しく作るときは、ノートかハブのソースモードで書いてください
